<a id="security-model"></a>
# セキュリティモデル

<a id="assets"></a>
## 資産

| 資産 | 重要性 | 機密度 |
|---|---|---|
| Terraform 入力 | インフラと秘密の可能性 | 中/高 |
| 実行成果物 | 検出、ログ、パッチ、モデル証拠 | 中 |
| モデルキー | LLM アクセス | 高 |
| LocalStack トークン | Azure エミュレーター起動 | 高 |
| Terraform state | 機密インフラ情報の可能性 | 高 |

<a id="trust-boundaries"></a>
## 信頼境界

- 操作者シェルから CLI。
- CLI からサンドボックス。
- CLI からモデル。
- 代理指示から許可ツール実行。
- ローカル成果物から公開文書。

<a id="identities"></a>
## ID

- 操作者：CLI を実行する信頼できる人間。
- レッド代理：ローカルサンドボックス限定の部分信頼攻撃者。
- ブルー代理：部分信頼の修正担当。
- 外部モデルサーバー：設定エンドポイントの動作にのみ信頼。
- CI：最小権限の一時的自動 ID。
- 顧客 AI 代理：専用代理 ID、ワークロード ID、サービスプリンシパル、IAM ロール、マネージド ID、利用者委任を使う部分信頼の非人間主体。
- ツール/実行 ID：ホスト、ゲートウェイ、コネクター、プラグイン、MCP、下流ツールの別主体。

ID 分析は次を区別します。

- 代理自身の ID と権限
- 操作を依頼した人間またはワークロード
- 委任/代理権限
- 実行環境とツールの ID
- 下流認証情報とトークン対象者
- 最終リソースと操作

双方の ID が認可に寄与した場合、一方だけに委任操作を帰属させてはいけません。

外部代理には有効な連携 ID が必要ですが十分ではありません。高影響認可は利用可能な実行証拠に依存すべきです。

- ワークロード ID が期待属性に結合
- デプロイダイジェストが承認済み署名成果物に一致
- ビルド来歴と発行者が検証済み
- 必要な実行/ハードウェア証明が新鮮かつ有効
- ネットワーク/ツールポリシーが承認プロファイルと一致
- 失効と監査制御が動作

証拠は暗号学的検証、提供者観測、操作者証言、推論、不明に分類します。不明を暗黙に信頼済みに昇格できません。

<a id="network-controls"></a>
## ネットワーク制御

V1 の既定はオフラインまたは LocalStack 形式のローカルです。実クラウド実行は既定範囲外です。

攻撃プローブは既定で `offline://...`、`local://...`、`127.0.0.1`、`localhost`、`localhost.localstack.cloud` などのみです。非ローカル HTTP(S) は明示的 `--allow-live-cloud` とイベントへの承認記録が必要です。`run --policy-file` 使用時は `allowed_target_hosts` で完全ホスト名や `*.domain` 接尾辞を要求できます。実クラウドアダプター追加前は組み込み対象もローカル/オフラインのままで、対象とイベントが示さない限り実クラウド検証と報告してはいけません。

<a id="secret-handling"></a>
## 秘密

- 環境変数から読みます。
- `.env` と Terraform state は除外します。
- `.env.example` は名前のみ、値なしです。
- ケース、サポート、画像、デモ公開前の成果物レビューは必須です。
- アップロードや公開前に `nullstate scrub` が秘密除去コピーを作ります。

<a id="container-security"></a>
## コンテナ安全性

LocalStack 等は実行依存で、同梱バイナリではありません。信頼できるイメージを取得し、生成ワークスペース外で任意のレッドコードを実行しないでください。

<a id="red-team-command-execution"></a>
## レッドコマンド実行

V1 ランナーは設計上制限されます。

- 生成 `attack.py` のみ実行。
- `attack.py` は実行ディレクトリ直下。
- マニフェスト使用時は `attack-manifest.json` も直下。
- 任意シェルでなく現行 Python で起動。
- 動的入力は `--target-url`、`--stage`、生成マニフェストパスのみ。
- コマンド、stdout、stderr、終了コード、URL、段階、開始/終了、時間を記録。
- プローブはテンプレート許可制で、モデルによる実行時生成ではない。
- タイムアウトを短くし、企業送信/長期保存前に出力取得を制限。

無制限ツール権限なしで、ローカル対象への実コマンドをデモできます。

企業向け強化で追加すべきもの：

- シナリオ/バックエンドごとの明示許可
- 実クラウド HTTP(S) の許可ホスト
- 組織固有除去ルールによる公開時サニタイズ
- 既定無効の `--allow-live-cloud`

<a id="cicd-security"></a>
## CI/CD 安全性

- PR はテスト、lint、型、依存監査。
- CodeQL は PR、push、週次。
- PR で依存レビュー。
- リリースは semver タグのみで、配布物と `sbom.spdx.json` の GitHub 証明を作成。
- 最小権限ワークフロー。

<a id="data-protection"></a>
## データ保護

公開前に確認します。トークン、実テナント/購読 ID、非公開 IP マップ、クラウド状態を公開しないでください。

<a id="known-risks"></a>
## 既知リスク

- 一部アダプターは完全実行でなく雛形。
- LocalStack Azure は外部設定とトークンが必要。
- オフライン指標はモデルを呼ばないためゼロトークン。
- 生成スクリプトは意図的に狭く、拡張しても許可制とサンドボックス制限を保持。

## 将来改善

- 組織固有の除去範囲拡張。
